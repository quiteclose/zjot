# zjot

[![CI](https://github.com/QuiteClose/zjot/actions/workflows/ci.yml/badge.svg)](https://github.com/QuiteClose/zjot/actions/workflows/ci.yml)

A [Djot](https://djot.net/) parser written in Zig. Produces HTML or AST output from Djot markup.

zjot passes all 261 test cases from the canonical [djot.js](https://github.com/jgm/djot.js) test suite.

## Build

Requires Zig 0.16 or later.

```
zig build
```

## CLI usage

```
zjot [OPTIONS] [--] [FILE]
```

If `FILE` is omitted or is `-`, reads from stdin. `--` ends the options, so a file whose name starts with `-` can follow it. The input is read a buffer at a time and the output is written block by block, so memory tracks the largest block rather than the document, until a block holds a reference-style link: that block waits as a tree and the output after it as text until the input ends, since a later definition may still change the link. Under `--ast --sourcepos`, a section's output waits until the heading that closes it. There is no size limit. If zjot exits non-zero part-way through a document, stdout may hold a truncated one.

**Options:**

| Flag | Description |
| --- | --- |
| `--ast` | Output AST instead of HTML |
| `--sourcepos` | Include source positions in AST output (requires `--ast`) |
| `-h`, `--help` | Show help |

**Examples:**

```sh
# Render Djot to HTML
echo 'Hello *world*' | zjot

# Render a file
zjot document.dj

# View the AST
echo '# Heading' | zjot --ast

# AST with source positions
zjot --ast --sourcepos document.dj
```

## Library usage

### Adding zjot as a dependency

Fetch the package and save it to your `build.zig.zon`:

```sh
zig fetch --save git+https://github.com/quiteclose/zjot.git
```

Then in your `build.zig`, import the dependency and add it to your module:

```zig
const zjot_dep = b.dependency("zjot", .{
    .target = target,
    .optimize = optimize,
});

// For an executable:
const exe = b.addExecutable(.{
    .name = "my-app",
    .root_module = b.createModule(.{
        .root_source_file = b.path("src/main.zig"),
        .target = target,
        .optimize = optimize,
        .imports = &.{
            .{ .name = "zjot", .module = zjot_dep.module("zjot") },
        },
    }),
});
```

### API

Once the dependency is wired up, import and use it:

```zig
const zjot = @import("zjot");

// Render Djot to HTML
const html = try zjot.toHtml(allocator, "Hello *world*");

// Render Djot to AST text
const ast_text = try zjot.toAst(allocator, "Hello *world*");

// AST with source positions
const ast_pos = try zjot.toAstOpts(allocator, input, true);
```

| Function | Description |
| --- | --- |
| `toHtml(allocator, input) ![]const u8` | Parse Djot and render to HTML |
| `toAst(allocator, input) ![]const u8` | Parse Djot and render to AST text |
| `toAstOpts(allocator, input, sourcepos) ![]const u8` | Parse Djot and render to AST text with optional source positions |
| `render(allocator, input, writer, opts) !void` | Render to a `std.Io.Writer` block by block; `opts` is `.{ .mode = .html \| .ast, .sourcepos = bool }` |
| `renderReader(allocator, reader, writer, opts) !void` | As `render`, reading the document from a `std.Io.Reader` a line at a time, so it need not be in memory |

The `to*` functions return owned slices that should be freed by the caller. `render` and
`renderReader` keep nothing past the call. Nodes are freed block by block as blocks are
written; what lives for the whole call is the definitions (all footnote content included),
the heading ids and what waits to be written. A block holding a reference-style link
waits as a tree until the input ends, since a later definition may still change the link,
and the blocks after it wait as rendered text; under `--ast --sourcepos` a section's blocks
wait as text until the heading that closes it. Otherwise memory tracks the largest block,
not the document, and with `renderReader` not the input either.

## Tests

```
zig build test
```

Runs 261 test cases vendored from the djot.js test suite, covering attributes, block quotes, code blocks, definition lists, emphasis, escapes, fenced divs, footnotes, headings, insert/delete/mark, links and images, lists, math, paragraphs, raw content, regressions, smart punctuation, spans, source positions, super/subscript, symbols, tables, task lists, thematic breaks, and verbatim, plus 495 cases of zjot's own in `test/zjot.test` and 115 in `test/grid.test` (every block family bare, under a block attribute, in a block quote and in a list item), all with expected output generated by djot.js 0.3.2.

## Architecture

zjot is a block-streaming renderer in one pass. The block parser is a container stack over the input's lines, the shape of djot.js's block parser: each line continues the open containers from the outermost in, opens new blocks while the innermost holds blocks, and what remains is lazy text or a blank line; it yields one block at a time (`Parser.nextBlock`) as a `Node` tree for that block alone, and there is no intermediate event stream and no tree of the whole document. Each block gets its heading ids as it arrives and is written as soon as nothing in it can still change: Djot lets a block refer to a later one, so a block holding a reference-style link waits in a queue until the input ends and the definitions are final, and the blocks behind it are rendered as they arrive and wait as text. Only the definitions, the ids and what waits live for the whole document.

```
src/
  root.zig           Public API: render, renderReader, toHtml, toAst, toAstOpts; the output queue
  main.zig           CLI binary, streaming its input
  node.zig           AST types (Node with a per-tag payload, Tag, Attr, SourcePos)
  Parser.zig         Block parsing: the container stack over lines, one block at a time
  leaf.zig           What one line says: block starts, list markers, fences, table rows
  Lines.zig          The line source, over a slice or a std.Io.Reader
  document.zig       Definitions, heading ids and implicit references, reference resolution, sections
  inline.zig         Inline parsing (emphasis, links, smart quotes, etc.)
  attributes.zig     Attribute parser ({#id .class key=value})
  html.zig           HTML renderer
  ast.zig            AST renderer
  LineMap.zig        Source position mapping for joined inline text
  test_runner.zig    Test harness
```
