# zjot

[![CI](https://github.com/QuiteClose/zjot/actions/workflows/ci.yml/badge.svg)](https://github.com/QuiteClose/zjot/actions/workflows/ci.yml)

A [Djot](https://djot.net/) parser written in Zig. Produces HTML or AST output from Djot markup.

zjot passes all 261 test cases from the canonical [djot.js](https://github.com/jgm/djot.js) test suite.

## Build

Requires Zig 0.15 or later.

```
zig build
```

## CLI usage

```
zjot [OPTIONS] [--] [FILE]
```

If `FILE` is omitted or is `-`, reads from stdin. `--` ends the options, so a file whose name starts with `-` can follow it. The whole input is read into memory and the output is written block by block, so memory tracks the input and the largest block rather than the document's structure. There is no size limit. If zjot exits non-zero part-way through a document, stdout may hold a truncated one.

**Options:**

| Flag | Description |
| --- | --- |
| `--ast` | Output AST instead of HTML |
| `--sourcepos` | Include source positions in AST output (requires `--ast`) |
| `-h`, `--help` | Show help |

**Examples:**

```sh
# Render Djot to HTML
echo 'Hello *world*' | zjot

# Render a file
zjot document.dj

# View the AST
echo '# Heading' | zjot --ast

# AST with source positions
zjot --ast --sourcepos document.dj
```

## Library usage

### Adding zjot as a dependency

Fetch the package and save it to your `build.zig.zon`:

```sh
zig fetch --save git+https://github.com/quiteclose/zjot.git
```

Then in your `build.zig`, import the dependency and add it to your module:

```zig
const zjot_dep = b.dependency("zjot", .{
    .target = target,
    .optimize = optimize,
});

// For an executable:
const exe = b.addExecutable(.{
    .name = "my-app",
    .root_module = b.createModule(.{
        .root_source_file = b.path("src/main.zig"),
        .target = target,
        .optimize = optimize,
        .imports = &.{
            .{ .name = "zjot", .module = zjot_dep.module("zjot") },
        },
    }),
});
```

### API

Once the dependency is wired up, import and use it:

```zig
const zjot = @import("zjot");

// Render Djot to HTML
const html = try zjot.toHtml(allocator, "Hello *world*");

// Render Djot to AST text
const ast_text = try zjot.toAst(allocator, "Hello *world*");

// AST with source positions
const ast_pos = try zjot.toAstOpts(allocator, input, true);
```

| Function | Description |
| --- | --- |
| `toHtml(allocator, input) ![]const u8` | Parse Djot and render to HTML |
| `toAst(allocator, input) ![]const u8` | Parse Djot and render to AST text |
| `toAstOpts(allocator, input, sourcepos) ![]const u8` | Parse Djot and render to AST text with optional source positions |
| `render(allocator, input, writer, opts) !void` | Render to a `std.Io.Writer` block by block; `opts` is `.{ .mode = .html \| .ast, .sourcepos = bool }` |

The `to*` functions return owned slices that should be freed by the caller. `render` keeps
nothing past the call. Nodes are freed block by block; what lives for the whole call is the
line index, the definitions (all footnote content included) and the heading survey, so
memory tracks the input and the largest block rather than the document's structure.

## Tests

```
zig build test
```

Runs 261 test cases vendored from the djot.js test suite, covering attributes, block quotes, code blocks, definition lists, emphasis, escapes, fenced divs, footnotes, headings, insert/delete/mark, links and images, lists, math, paragraphs, raw content, regressions, smart punctuation, spans, source positions, super/subscript, symbols, tables, task lists, thematic breaks, and verbatim, plus 296 cases of zjot's own in `test/zjot.test` whose expected output was generated by djot.js 0.3.2.

## Architecture

zjot is a block-streaming renderer in two passes. The block parser is a recursive descent over the input's lines that yields one block at a time (`Parser.nextBlock`) as a `Node` tree for that block alone; there is no intermediate event stream and no tree of the whole document. `render` runs the parser twice, because Djot lets a block refer to a later one: the first pass surveys the document (heading ids, implicit references, link and footnote definitions), the second resolves each block against that survey, wraps headings in sections and writes the block, resetting the block arena after each. Only the line index, the definitions and the survey live for the whole document.

```
src/
  root.zig           Public API
  main.zig           CLI binary
  node.zig           AST types (Node, Tag, Attr, SourcePos)
  Parser.zig         Block parsing + list helpers + position tracking
  document.zig       Heading ids, reference resolution, sections
  inline.zig         Inline parsing (emphasis, links, smart quotes, etc.)
  attributes.zig     Attribute parser ({#id .class key=value})
  html.zig           HTML renderer
  ast.zig            AST renderer
  LineMap.zig        Source position mapping for joined inline text
  test_runner.zig    Test harness
```
